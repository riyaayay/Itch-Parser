tick2trade-fpga: Architecture Specification
(v3)
Riya Rathod · Oct 28, 2026 · Status: plan only, nothing built
This is the single source of truth for building tick2trade-fpga on top of tmlee06/Itch-
Parser. Anything marked [N] is normative: code or a test that disagrees with it is wrong, or
this spec must be changed first.
Provenance of this revision. Sections 1 and 2 are the approved text. Sections 3 to 16 were
written after reading every RTL, testbench and data file of the upstream repository on
Oct 28, 2026. Nothing was executed. Anything in section 3 marked [VERIFY] comes from
reading rendered source and must be confirmed by a run at T0. Where this pass had to
choose a behaviour the owner has not approved, it is listed in section 16.3 (C-choices) and
stays normative until the owner changes it.
1. How to use this spec
Tags. [N] normative. [I] informative (a recommendation the implementer may change).
[VERIFY-n] a fact about the upstream repo or a tool that must be confirmed by reading it
at T0. [TBD-n] a choice the owner has not made yet (register in section 16).
Precedence. This spec, then committed code, then the upstream README. The README
claims (under 840 ns, about 700 MHz, 11 LUTs at 100 MHz) were never reproduced and
must not be copied into this project.
Rules for whoever writes the code (human or Claude):
1. Read sections 3, 4 and the section of the module being built before writing anything.
Never guess a port, width or byte offset: it is in this document or it is a [TBD].
2. One task (section 15) per change set. The commit message starts with the task id, for
example T5: order table bypass .
3. Never edit anything under upstream/ . Wrap or re-implement instead.
4. Interface changes (ports, widths, formats) are made in this spec first and in code in the
same commit.
5. Every normative behaviour has a test id in section 12. A module is done only when its
listed tests pass and their logs are committed to reports/sim/ .
6. A number in a README, resume line or commit message must link to a file in reports/
plus a commit hash, and carry exactly one label: measured, bounded-proven, reported,
computed or estimate (section 13).

4.3 Clocking, reset, elasticity [N]
1. One clock clk , rising edge. Reset rst  is synchronous, active high, and shallow (a
registered reset fan-out is allowed). t2t_kernel  converts ap_rst_n  to rst  through a
two-flop synchroniser.
2. Every module output is registered.
3. Two handshake classes only. H1 valid-only, fixed latency, never stalls. H2 FIFO with an
almost-full flag and a credit margin.
4. The elastic points are exactly: ING  (before the framer), FA  (between filter and table),
FB  (between table and book), TXF  (after the encoder). Every other stage is H1.

5. Credit rule: the stage that pops or issues into an H1 chain stops issuing while the
downstream FIFO afull  is set. afull  asserts at occupancy >= depth - margin, with
margin >= (register depth of the unstoppable chain after the issue point) + 2.
6. Any write into a full FA , FB  or TXF  is a design error: it raises fatal_overflow , which
sets session_invalid , and the testbench fails on it.
7. FIFOs are first-word-fall-through with a registered read. Minimum traversal is 2 cycles.
Occupancy is a power-of-two depth.

Why resync is not attempted: a lost or skipped handled message means the book may be
missing an add or delete, so market state can no longer be proven exact. Framing itself
resumes at the next frame (A1), but the book stays untrusted until session reset.
Session reset sequence (triggered by CTRL.session_reset , or by hardware rst ):
1. init_busy  goes high. All beats arriving while it is high are discarded and counted
( rx_dropped_init ).
2. The framer enters SYNC_WAIT : it discards beats until one with tlast=1  has passed,
then starts at the next beat.
3. The order table sweeps all sets to invalid at one set per cycle ( 2^TABLE_AW  cycles).
Ladders, hidden counts, corrupt , per-symbol seq , the message index and
session_invalid  clear in one cycle.
4. init_busy  falls after the sweep plus 4 cycles.
5. Not cleared: counters (unless CTRL.clear_counters ), kill, risk positions,
configuration, tx_fault .
Caveat [N]: a reset is exact only at the start of a feed (A3). A mid-stream reset gives a
book missing every order that was resting before it. The design does not detect that; it
shows up as ref_miss  counts, and the host owns the decision.
Every simulation vector starts with a sync frame: one beat, tkeep=64'h3 , tlast=1 ,
tdata=0 . It is discarded by SYNC_WAIT  and exists only to establish alignment.

4.6 Numeric conventions [N]
All multi-byte ITCH and outbound fields are big-endian on the wire. Inside the core they
are plain numbers. Price unit is 1/10000 USD, unsigned 32-bit. Stock is 8 ASCII bytes, space
padded, character 0 in bits [63:56] . Side bit: 0 = bid (buy), 1 = ask (sell). Counters are 32-
bit and saturate at 0xFFFFFFFF .

araddr[11:0] , arvalid , arready , rdata[31:0] , rresp[1:0] , rvalid , rready .
Protocol: a write is accepted when both awvalid  and wvalid  are high in the same cycle;
bvalid  rises the next cycle and holds until bready . A read is accepted on arvalid ;
rvalid  rises the next cycle and holds until rready . One transaction outstanding per
channel. bvalid  is never high without a write (this fixes upstream finding F11). wstrb  is
honoured per byte lane. Response is OKAY (0) on success; SLVERR (2) on a write to a
read-only register, an unmapped address, or a rejected write (below). Reads of unmapped
addresses return 0xDEADBEEF  with OKAY, as upstream did. Coherence: registers marked
S read a shadow that is latched all at once by CTRL.snapshot ; before the first snapshot
the shadow is 0.
